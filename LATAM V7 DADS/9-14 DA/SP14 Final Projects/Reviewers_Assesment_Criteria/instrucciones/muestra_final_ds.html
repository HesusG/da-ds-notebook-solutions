Hallazgos¶

  • En el dataset "llamadas" se encontraron valores nulos en las columnas "internal" (117 nulos) y en la columna "operator_id" (8172 nulos). El hecho de que haya operator_id nulos puede indicar llamadas automáticas, errores de registro o que no había operador asignado (lo verificaremos más adelante).
  • La columna "date" del datasetestá como object y debe convertirse a datetime
  • En el dataset "clientes" no se hallaron valores nulos
  • La columna "date_start" también está como object y debe convertirse a datetime

Decisiones

  • Conservar todas las llamadas entrantes (in) sin operador, porque son parte del indicador de ineficacia (muchas llamadas entrantes perdidas indican mal desempeño global, incluso si no se asignó operador).
  • Excluir las llamadas salientes (out) sin operador del análisis, porque no nos aportan nada útil sobre eficiencia.
  • Crear dos subconjuntos:
    llamadas_operadores: solo con operador válido (para métricas por operador).
    llamadas_entrantes_sin_operador: las entrantes sin operador (para entender el volumen total de llamadas perdidas).

In [5]:
# Rellenar internal nulo
llamada['internal'] = llamada['internal'].fillna('unknown')

# Separar llamadas con y sin operador
llamadas_operadores = llamada[llamada['operator_id'].notna()].copy()
llamadas_sin_operador = llamada[llamada['operator_id'].isna()].copy()

# De las sin operador, conservar solo las entrantes
llamadas_entrantes_sin_operador = llamadas_sin_operador[llamadas_sin_operador['direction'] == 'in']

print(f"Llamadas totales: {llamada.shape[0]}")

def clasificar_percentil(serie):
    p25 = np.percentile(serie, 25)
    p75 = np.percentile(serie, 75)
    p90 = np.percentile(serie, 90)

    def clasificar(x):
        if x > p90:
            return 'muy ineficiente'
        elif x > p75:
            return 'ineficiente'
        elif x < p25:
            return 'eficiente'
        else:
            return 'promedio'

    return serie.apply(clasificar)

Clasificación de operadores mediante percentiles¶

Para identificar operadores con bajo desempeño, se utilizó un método de clasificación basado en percentiles, que permite segmentar a los operadores de acuerdo con su posición relativa dentro de la distribución de cada métrica.

Se calcularon percentiles para las tres métricas críticas:

  • Porcentaje de llamadas perdidas

  • Tiempo promedio de espera

  • Duración promedio de la llamada

A partir de estos valores, cada operador fue asignado a una de las siguientes categorías:

Muy ineficiente: operadores por encima del percentil 90 (peor 10% del sistema).

Ineficiente: operadores entre los percentiles 75 y 90.

Promedio: operadores entre los percentiles 25 y 75.

Eficiente: operadores por debajo del percentil 25 (mejor 25%).

Este enfoque permite:

  • Detectar operadores con desempeño críticamente bajo

  • Comparar operadores independientemente de la escala de cada métrica

  • Identificar patrones de ineficiencia en grupos específicos

  • Priorizar acciones de mejora y capacitación

Ranking final de ineficiencia por percentiles (Cuantificable)¶

Tras clasificar a cada operador según su posición en los percentiles de tres métricas clave: porcentaje de llamadas perdidas, tiempo promedio de espera y duración promedio de llamada, se construyó un Índice Global de Ineficiencia (IGI).

Cada categoría se transformó en un puntaje:

  • Muy ineficiente = 3 puntos

  • Ineficiente = 2 puntos

  • Promedio = 1 punto

  • Eficiente = 0 puntos

El índice se obtuvo sumando los puntajes asignados a cada una de las métricas. El rango posible de valores va de 0 (operadores muy eficientes) a 9 (operadores con desempeño crítico).

Finalmente, se generó un ranking, donde:

1 = operador más ineficiente (valores mayores indican mejor desempeño relativo)

Este ranking permite identificar de forma clara y objetiva qué operadores requieren atención prioritaria, capacitación adicional o redistribución de carga.

Conclusiones integradas entre Percentiles vs Clustering¶
El análisis combinado utilizando clasificación por percentiles ("umbrales estadísiticos") y clustering no supervisado permitió identificar patrones consistentes en el desempeño de los 1,092 operadores analizados. Los resultados de ambas metodologías coincidieron en la definición de segmentos de eficiencia, proporcionando una base sólida para la toma de decisiones operativas.


1. Identificación consistente de operadores eficientes


La clasificación por percentiles determinó que 379 operadores presentan un desempeño eficiente. Este resultado coincide con la estructura observada mediante clustering, donde el Cluster 0 agrupa principalmente a operadores altamente eficientes:


337 operadores eficientes, equivalentes al 89% del cluster.


Estos hallazgos confirman la existencia de un segmento claramente diferenciado de operadores con buen desempeño, caracterizado por bajas pérdidas, tiempos de espera controlados y duraciones de llamada adecuadas.


2. Concentración de operadores ineficientes en clusters críticos


La metodología estadística identificó 105 operadores muy ineficientes. El algoritmo de clustering mostró una fuerte concentración de este grupo en dos segmentos específicos:


Cluster 2, donde se ubican 77 operadores muy ineficientes,
